# Google Classroom 繳交與批閱追蹤

## 啟動時確認

1. 在對話開頭取得要檢查的 Google Classroom 課程網址；接受多個網址，先列出解析出的課程名稱與課程 ID，確認登入的教師帳號有權查看。不要默默掃描其他課程。
2. 取得使用者提供的「課程 ID、Google 帳號、座號」對照資料。可讀取使用者提供的 CSV、試算表或貼上的表格；同一帳號在不同課程可有不同座號。不要把真實對照資料、學生帳號或 Classroom 存取憑證提交到 GitHub。
3. 對照資料尚未提供時，仍可做總數統計與檢查，但個別紀錄只顯示「座號待對照」；不要用 Google 帳號名稱、姓名或顯示名稱替代座號。無法唯一對照時，也使用此標記並報告待對照筆數。
4. 逾期門檻預設為 5 個日曆日；允許使用者在執行時或設定中改為其他正整數天數。預設時區為 `Asia/Taipei`。
5. 問使用者要立即手動檢查，或另外建立每日排程。每日排程預設台灣時間 23:00；若使用者指定其他時間，依指定時間設定。不要因為安裝或閱讀本 skill 就自行建立排程。

## 讀取與判定

優先使用已登入 Google Classroom 的 Chrome 工作階段，以及當時可用的受授權 Classroom 工具。只讀取，不評分、不新增留言、不退回作業。登入、權限或驗證中斷時，停止該課程並明確列為「未完成檢查」，不可把未知狀態當作零繳交。

對每門指定課程，列出所有作業。對每份準時、遲交及重新繳交的提交紀錄，使用學生**最近一次繳交**的時間與目前狀態。若 Classroom 只提供相對時間，開啟作業記錄取得可確認的絕對時間；取不到時將逾期狀態標為「時間待確認」，不可猜測。

一份作業符合任一條件即為「已批閱」：

- Classroom 顯示該學生該作業在最近一次繳交後已正式發還。
- 教師在該作業的私人留言中，於最近一次繳交後傳送了至少一個網址前綴為 `https://drive.google` 的批改檔案連結。連結可以是留言文字或可點擊連結；不要求輸入分數，也不要求留言含有固定的「批改檔案」四字。學生留言或學生附件中的 Drive 網址不算。

若無法確認留言作者或留言／發還時間是否晚於最近一次重繳，標示「批閱待確認」，不要推斷為已批閱。單純有分數、一般私人留言、已檢視、學生上傳的 Drive 檔案，都不構成本 skill 的批閱依據。

逾期計算：將最近一次繳交時間與檢查時間轉為 `Asia/Taipei` 的日期，計算兩個日期相差的日曆天數。**未批閱且差值大於或等於設定門檻**才列為逾期。例如 10 月 1 日繳交、門檻 5 天，從 10 月 6 日的檢查起列入；重繳則重新起算。未知的批閱狀態或時間不得列為已確認逾期。

## 座號對照

以課程 ID 與可確認的 Google 帳號（電子郵件）做唯一對照；若 Classroom 介面沒有顯示電子郵件，可使用名冊中的穩定學生 ID，但必須由使用者提供或可驗證地建立 ID 與座號關係。姓名相同、帳號缺失、對照重複或座號衝突時，不要猜測。對照資料可留在使用者指定的本機私有位置；排程執行前確認該位置在執行主機上可讀。報表及 LINE 訊息只用座號識別學生。

## 輸出

每次檢查先顯示繁體中文摘要：檢查時間、課程數、作業總數、繳交總數、已批閱數、未批閱數、批閱待確認數、逾期數、座號待對照數、未完成檢查數，以及門檻天數。已批閱者只計入摘要，不列在明細。

接著提供一張**待處理明細**表：只列未批閱及批閱待確認的提交；欄位為課程、作業、座號、最近繳交時間、已過日曆天數、狀態。不要列出已批閱者、批閱判定依據、批改檔案網址或零繳交作業。依已過日曆天數由多到少排序；天數待確認者排最後。同天數時先依繳交時間較早者，再依課程與作業排序。

若沒有逾期，明確寫「目前沒有已確認的逾期未批閱作業」。可將作業名稱連到 Classroom 作業頁面，方便教師開啟。不要在報表、通知或公開檔案中顯示學生姓名或 Google 帳號。

## 通知與排程

手動執行時，直接在目前對話顯示完整摘要與一張待處理表。若使用者選擇每日監控，透過 Codex 的排程／heartbeat 工具建立追蹤，不手寫排程指令；在建立前確認課程網址、私有對照資料的可用位置、執行主機與通知方式。排程預設每日 `23:00 Asia/Taipei`。使用者已指定每天都回報，所以每天產生完整對話報表，包括沒有新增繳交或逾期的日子。LINE 摘要也不要包含批閱判定依據或批改檔案網址。

若 M1 上有可用且已設定收件人的「顧店 app」官方 LINE 傳訊能力，每日傳送**摘要**：每門課的繳交、未批閱、逾期與待對照數，並列出逾期的「座號＋作業」；篇幅過長時保留各課程統計與逾期總數，在 Codex 對話保留完整明細。使用既有收件設定，不在 skill 或 repository 中保存 LINE token、User ID 或學生資料。只有傳送工具回報成功時才聲稱 LINE 已通知；能力不存在、設定不完整或傳送失敗時，在 Codex 報告具體原因並保留完整報表。不要以 LINE 個人帳號 app 或未驗證的連結代替官方帳號傳送。

首次執行要建立當時的完整基準並回報；之後每次仍產生當日完整報表。設定或來源缺失時，指出需要使用者補的項目，並完成其餘可安全檢查的課程。
